## 一、核心研究結論（已經很穩固，多方法收斂）

**PTT情緒因子對LSTM股價預測的貢獻，測不出統計上顯著的效果。** 這個結論用了以下方法
交叉驗證，全部指向同一個答案：

1. 30檔股票（自己爬蟲）：20組隨機種子，平均差異+0.20pp，95%CI[-0.18,+0.58]涵蓋零
2. 267檔股票（組員爬蟲，獨立資料源）：20組隨機種子，平均差異-0.063pp，95%CI[-0.32,+0.19]涵蓋零
3. Ensemble平均降噪（10-seed平均預測）：差異仍只有-0.14pp
4. 換模型（XGBoost迴歸/分類）：情緒因子重要性排最後
5. 換情緒分類LLM（Taiwan-LLM）：準確率、Macro-F1都更差，不是換模型能解決的
6. Ground-truth品質檢查：人工-Claude標註Kappa=0.52（中等一致性），證明這任務本身標籤就有模糊空間，62-68%準確率的天花板可能是任務難度造成的，不是方法選錯

已有簡報 `ppt_build/final_report_267.pptx`（12頁，PTT267檔版本，validate.py通過）。

  落後情緒因子依然測不出穩健效果。同日訊號的巨大效應值(+0.95%/天)再次印證洩漏疑慮，不是好消息。
  **建議**：到此已用MAPE迴歸(3版本)+AUC漲跌(全體+4分層)+CMoney獨立驗證+異常尖峰偵測+橫截面多空共7種方法交叉驗證，
  收斂一致，不建議再繼續搜索新的檢驗角度，可以開始收斂寫報告。

### 二之五、2026-09-23 重要發現：CMoney留言也有日期錯置問題，比PTT更嚴重

- **起因**：使用者質疑「CMoney有精確時間戳，同日訊號是不是其實還能用？」查證後發現雖然留言本身有正確createTime，

  跟PTT的斷句/歸屬問題是同一種機制，只是換了個資料源重現。
- **量化(全部427,454則留言)**：17.1%的留言(72,972則)實際發文日期比文章晚1天以上，gap_days最大到1728天(約4.7年)。
- **更嚴重的發現**：留言爬蟲(`crawl_cmoney_comments.py`)完全沒有套用文章爬蟲的日期篩選(--start/--end)。
  文章本身確實侷限在2020-01-02~2024-12-31(符合設定的2020-2024範圍)，但留言最晚到**2026-09-13**
  (爬蟲實際執行的時間點附近)，代表部分留言是2025、2026年才回覆2020-2024年舊文章，混進了跟「那一天」
  完全無關的內容，被`breeze_infer_cmoney.py`誤標成文章發布當天的情緒。
- **快速驗證嘗試**(10檔留言量最大的股票、3萬則抽樣、未含文章全文)：舊版(文章日期) vs 新版(留言自己的真實日期)的
  同日多空價差：+0.97%/天(p=0.27) vs +1.40%/天(p=0.07)，兩者都不顯著，樣本太小(可交易天數僅17~21天)無法下定論，
  不能說修正後訊號消失或存在。(過程中也嘗試優化`breeze_infer_267_fast.py`支援不同長度padding分批處理，但改成
  對整個序列算logits反而更慢，已放棄；`classify_sorted`/`_constrained_group_padded`方法保留在程式碼中但未驗證
  正確性，不建議使用。)
- **要有可信結論，需要**：用完整37萬則(10檔)或42.7萬則(全部)留言依真實日期重新分類，套進正式的

  4小時(不含文章全文，全文因長度分散、批次效率差會更慢)；使用者評估後決定不投入這幾小時，改為誠實記錄此限制。
- **報告限制章節應納入**：CMoney情緒因子的同日/落後歸屬皆可能受留言日期錯置影響，且錯置幅度(最長約4.7年)

## 三、環境限制（重要，會反覆遇到）

1. **背景process會被無預警關掉**：這禮拜已經發生兩次——一次是Claude Desktop
   自動更新卡住導致app打不開，一次是對話session結束時被一起關掉，都**不是程式
   bug**。因為都有checkpoint機制，資料不會遺失，但要記得每次重新開始對話/重開app
   後，先確認背景process是不是還活著（`ps aux | grep python`），死了要重啟。
2. **GPU是桌機的RTX 5060 8GB**：batch_size太大（例如32）反而會因為VRAM接近滿載
   讓效能崩潰變慢，Breeze-7B推論用batch_size=16是實測最快；LoRA微調batch_size=1
   +關掉gradient checkpointing是實測最快（開著gradient checkpointing會慢250倍）。
3. **這個Claude Code session實際跑在使用者的桌機上**，不是筆電，就算使用者用筆電
   打字，所有操作（跑爬蟲、開瀏覽器、用GPU）都是在桌機上執行。
